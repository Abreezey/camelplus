# Module B: normalization and MCP gateway

Review status (2026-10-15): the three independent B defects in
[module-b-review.md](../module-b-review.md) are fixed. All 517 tests pass, including
the Conda environment run. The B/C execution contract and real sandbox integration
are still pending; these results do not constitute end-to-end security acceptance.

Problem: tools currently have no common effect normalizer or pinned MCP entry
point. Policy decisions therefore cannot cover filesystem, shell, network and
Git calls consistently (plan.md §2.B).

Assumptions: deployment configuration, argument labels, server pins, tool-to-effect
bindings and the approval channel are trusted. Tool manifests, arguments and
returns are untrusted. B does not replace C's OS sandbox or D's detector. A's
frozen models and C's public signatures stay intact.

Minimal implementation: bounded ingress views; filesystem, Bash AST, network,
Git and configured MCP normalization; an audited gateway with manifest pinning,
schema validation, atomic confirmation consumption and ticket-checked dispatch;
stdio and Streamable HTTP adapters. Unknown/dynamic effects fail closed. Network
transport pins validated IPs and rejects redirects. Only the gateway owns upstream
sessions; downstream clients cannot register servers or approve calls.

Acceptance: normal, denied, boundary and fault cases; adversarial corpus for paths,
shell expansions/pipelines/encoding, SSRF/rebinding and manifest changes; actual
stdio/HTTP proxy roundtrips; differential filesystem/Git checks; coverage report;
all existing tests, Ruff, formatting and Pyright pass. Deployment must keep
upstream endpoints inaccessible to the Agent (C's OS/network responsibility).
